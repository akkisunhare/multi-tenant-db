# Production-Grade Multi-Tenant User Management Backend

A high-performance, secure, and production-ready Multi-Tenant User Management Backend built with **Node.js**, **Express.js**, **TypeScript**, **MongoDB (Mongoose)**, and **Redis**.

The system strictly enforces a **database-per-tenant isolation architecture**, independent multi-tier authentication systems with cryptographic anti-cross-login guards, dynamic connection pooling, tenant-scoped CRUD operations, and Redis-powered menu caching.

---

## 1. Architecture & Design Principles

### A. Database-Per-Tenant Isolation
Every tenant (Master) is provisioned with a dedicated, isolated MongoDB database. Tenant collections (`users`, `datas`) never coexist in a shared database.

```text
MongoDB Cluster
│
├── central_db                     # System-wide administrative context
│   ├── superadmins                # Superadmin credentials
│   └── masters                    # Masters metadata & tenant database mapping
│
├── public_db                      # Independent public portal database
│   └── publicusers                # Self-registered public users
│
├── tenant_a8f21                   # Master A's completely isolated database
│   ├── users                      # Users created by Master A
│   └── datas                      # Business data records belonging to Tenant A
│
└── tenant_b7d92                   # Master B's completely isolated database
    ├── users                      # Users created by Master B
    └── datas                      # Business data records belonging to Tenant B
```

### B. Dynamic Tenant Connection Pool Manager
- **No connection exhaustion**: Uses a cached connection registry (`Map<dbName, Connection>`) with an LRU pruning lifecycle.
- **Dedicated models**: Uses `connection.model()` per tenant connection. The global `mongoose.model()` is never used for tenant-specific schemas.
- **Server-controlled provisioning**: Tenant database names are generated by the server (`tenant_<crypto_hex>`), preventing tenant database spoofing.
- **Index Synchronization**: Automatically initializes collections and creates unique indexes upon master creation.

### C. Independent Authentication & Anti-Cross-Login Matrix
Four independent authentication systems with separate JWT secrets, cryptographic issuer/audience checks, and strict role guards:

| Account Type | Stored In | Login Endpoint | Token Payload Role | Permitted Access Scope |
| :--- | :--- | :--- | :--- | :--- |
| **Superadmin** | `central_db` | `POST /superadmin/login` | `superadmin` | `/superadmin/*` only |
| **Master** | `central_db` | `POST /master/login` | `master` | `/master/*`, `/data/*` (full tenant scope) |
| **Public User** | `public_db` | `POST /auth/login` | `public` | `/auth/profile` only |
| **Master User** | `tenant_<id>` | `POST /master/user/login` | `master-user` | `/master/user/profile`, `/data/*` (own scope) |

#### Cross-Login Rejection:
- A `Public User` cannot log in via `/master/login` or `/master/user/login`, and cannot access `/master/*` or `/data/*` (HTTP 403 Forbidden).
- A `Master-created User` cannot log in via `/auth/login`, and cannot access `/auth/profile` (HTTP 403 Forbidden).
- Masters cannot access or modify records of other masters (HTTP 404 Not Found).

## 4. Prerequisites & Installation

### Prerequisites
1. **Node.js** (v18 or higher, v20 recommended)
2. **MongoDB** (running locally on port `27017` or a MongoDB Atlas URI)
3. **Redis** (optional - running locally on port `6379`; application automatically utilizes built-in fallback cache if Redis is offline)

### Step 1: Install Dependencies
```bash
npm install
```

### Step 2: Configure Environment Variables
Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```
Default configuration in `.env`:
```env
PORT=5000
NODE_ENV=development

MONGODB_URI=mongodb://127.0.0.1:27017
CENTRAL_DB_NAME=central_db
PUBLIC_DB_NAME=public_db

REDIS_URL=redis://127.0.0.1:6379
REDIS_ENABLED=true

JWT_SUPERADMIN_SECRET=superadmin_jwt_secret_key_prod_quality_2026_x1
JWT_MASTER_SECRET=master_jwt_secret_key_prod_quality_2026_x2
JWT_PUBLIC_SECRET=public_jwt_secret_key_prod_quality_2026_x3
JWT_MASTER_USER_SECRET=master_user_jwt_secret_key_prod_quality_2026_x4

SUPERADMIN_EMAIL=admin@example.com
SUPERADMIN_PASSWORD=Admin@123
```

### Step 3: Seed Superadmin (Optional — Server seeds automatically on start)
```bash
npm run seed
```

### Step 4: Start the Server
```bash
# Development mode (with live reload)
npm run dev

# Production build & run
npm run build
npm start
```

## 6. API Reference & Sample Payloads

All responses follow a consistent format:
```json
{
  "success": true,
  "message": "Operation successful",
  "data": {}
}
```

### Module A: Superadmin APIs
#### 1. Superadmin Login
- **Endpoint**: `POST /superadmin/login`
- **Request Body**:
  ```json
  {
    "email": "admin@example.com",
    "password": "Admin@123"
  }
  ```
- **Response** (`200 OK`):
  ```json
  {
    "success": true,
    "message": "Superadmin logged in successfully",
    "data": {
      "token": "eyJhbGciOi...",
      "superadmin": {
        "id": "6afd38...",
        "name": "Super Admin",
        "email": "admin@example.com"
      }
    }
  }
  ```

#### 2. Create Master & Provision Tenant DB
- **Endpoint**: `POST /superadmin/master`
- **Headers**: `Authorization: Bearer <superadminToken>`
- **Request Body**:
  ```json
  {
    "name": "Acme Corp",
    "email": "acme@example.com",
    "password": "Master@123"
  }
  ```
- **Response** (`201 Created`):
  ```json
  {
    "success": true,
    "message": "Master and isolated tenant database provisioned successfully",
    "data": {
      "id": "6afd39...",
      "name": "Acme Corp",
      "email": "acme@example.com",
      "dbName": "tenant_a48f9b",
      "status": "active"
    }
  }
  ```

#### 3. List Masters
- **Endpoint**: `GET /superadmin/masters?page=1&limit=10`
- **Headers**: `Authorization: Bearer <superadminToken>`

---

### Module B: Master APIs
#### 1. Master Login
- **Endpoint**: `POST /master/login`
- **Request Body**:
  ```json
  {
    "email": "acme@example.com",
    "password": "Master@123"
  }
  ```
- **Response** (`200 OK`):
  ```json
  {
    "success": true,
    "message": "Master logged in successfully",
    "data": {
      "token": "eyJhbGciOi...",
      "master": {
        "id": "6afd39...",
        "name": "Acme Corp",
        "email": "acme@example.com",
        "dbName": "tenant_a48f9b",
        "status": "active"
      }
    }
  }
  ```

#### 2. Master Creates Tenant User
- **Endpoint**: `POST /master/user`
- **Headers**: `Authorization: Bearer <masterToken>`
- **Request Body**:
  ```json
  {
    "name": "Rahul Sharma",
    "email": "rahul@example.com",
    "password": "User@123"
  }
  ```
- **Response** (`201 Created`):
  ```json
  {
    "success": true,
    "message": "Tenant user created successfully",
    "data": {
      "id": "6afd40...",
      "name": "Rahul Sharma",
      "email": "rahul@example.com",
      "masterId": "6afd39..."
    }
  }
  ```

#### 3. Master Lists Tenant Users
- **Endpoint**: `GET /master/users?page=1&limit=10`
- **Headers**: `Authorization: Bearer <masterToken>`

#### 4. Master Menu (Redis Caching)
- **Endpoint**: `GET /master/menu`
- **Headers**: `Authorization: Bearer <masterToken>` or `<masterUserToken>`
- **Response** (`200 OK`):
  ```json
  {
    "success": true,
    "message": "Menu retrieved successfully",
    "data": {
      "menu": [
        { "id": "dashboard", "title": "Dashboard", "path": "/dashboard", "icon": "dashboard" },
        { "id": "users", "title": "Users", "path": "/users", "icon": "people" },
        { "id": "reports", "title": "Reports", "path": "/reports", "icon": "bar_chart" },
        { "id": "settings", "title": "Settings", "path": "/settings", "icon": "settings" }
      ],
      "source": "cache"
    }
  }
  ```

### Module D: Master User APIs
#### 1. Master User Login
- **Endpoint**: `POST /master/user/login`
- **Request Body**:
  ```json
  {
    "masterEmail": "acme@example.com",
    "email": "rahul@example.com",
    "password": "User@123"
  }
  ```

#### 2. Master User Profile
- **Endpoint**: `GET /master/user/profile`
- **Headers**: `Authorization: Bearer <masterUserToken>`

---

### Module E: Common Tenant-Specific CRUD APIs
Supported by both `Master JWT` and `Master User JWT`.
- `POST /data` — Create item in tenant database
- `GET /data` — List tenant items (Masters see all items in tenant; Master users see only their own)
- `GET /data/:id` — Get tenant item by ID (Returns 404 if outside permitted scope)
- `PUT /data/:id` — Update tenant item by ID
- `DELETE /data/:id` — Delete tenant item by ID

## 7. Postman Collection

A complete, pre-configured collection is included: `postman_collection.json`.

### How to use:
1. Open Postman -> Click **Import** -> Select `postman_collection.json`.
2. The collection includes pre-configured collection variables (`baseUrl`, `superadminToken`, `masterToken`, `publicToken`, `masterUserToken`, `tenantDataId`).
3. Running `POST /superadmin/login` or `POST /master/login` automatically extracts and sets the tokens in collection variables for all subsequent requests.
